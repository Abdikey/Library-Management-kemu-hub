1. Project overview

SchoolLib is a library management system for a school. A librarian can keep a catalogue of books, a register of students, issue books, accept returns and see which books are late.

It is built with plain HTML, CSS and JavaScript (ES6 modules). There is no framework and nothing to install or compile. The data is stored in a Supabase (PostgreSQL) database, which the pages talk to using the Supabase JavaScript client loaded from a CDN.

2. Setup guide

  1. Create a free account at supabase.com and create a new project.
  2. In the project, open SQL Editor → New query, paste everything from sql/schema.sql and click Run. This creates the tables, triggers, the view and the sample data.
  3. Open Project Settings → API and copy the Project URL and the anon public key.
  4. Paste both into js/config.js: 
    export const SUPABASE_URL = "https://xxxx.supabase.co";
export const SUPABASE_ANON_KEY = "eyJhbGciOi...";
  5. Open index.html in a browser, or serve the folder with any static server, for example python -m http.server.

If the keys are still the placeholders, every page shows a yellow warning at the top and no data will load.

3. Database design

books

  • id — unique identifier
  • title, author, category, publisher, year
  • isbn — unique, so the same book cannot be added twice
  • total_copies — how many copies the library owns
  • available_copies — how many are on the shelf right now

students

  • admission_no — unique for every student
  • full_name, class, email, phone

borrowings

  • book_id and student_id — links to the two tables above
  • issue_date, due_date, return_date
  • status — only borrowed or returned
  • fine_amount — money owed for a late return

Triggers and the view

  • Inserting a borrowing takes one copy off the shelf automatically.
  • Filling in a return date puts the copy back and sets the status to returned.
  • borrowings_view joins the three tables and calculates is_overdue every time it is read, so "overdue" is never stored and can never be out of date.

Because the database does this work, the JavaScript never edits available_copies itself and the numbers cannot drift.

6. How the main features work

Shared code

js/app.js holds everything used by more than one page: the sidebar, the sortable and paginated table, modals, toast messages, date helpers and a function that escapes text before it is put into the page. Nothing is copied between pages.

Issuing a book

  1. The form only lists books that still have a free copy.
  2. The borrowing limit and the duplicate-title rule are checked.
  3. The free copy is checked once more against the database, in case somebody else took the last one.
  4. The row is inserted and the trigger updates the shelf count.

Returning a book

The fine is worked out from the return date before saving, and is shown in the dialog so the librarian can see it first. Saving the return date makes the trigger put the copy back on the shelf.

Searching, sorting and printing

Search and filters run in the browser on data already loaded, so they feel instant. Every table header can be clicked to sort, and each page has a print button that hides the menu, buttons and pagination.

7. Security note

There is no login in this project, so Row Level Security policies allow anyone with the anon key to read and write. That is acceptable for a classroom demo.

A real library system would add Supabase authentication and restrict adding, editing and deleting to librarian accounts, while students would only be able to read the catalogue.

8. Testing checklist

  • Add a book with an ISBN that already exists — a clear message appears.
  • Add a student with a repeated admission number — a clear message appears.
  • Issue a book and check the available copies drop by one.
  • Issue a fourth book to the same student — it is refused by the limit.
  • Return a book with a past due date — the fine is calculated and shown.
  • Try to delete a book or student that has borrowing history — it is refused.
  • Open the app on a phone-sized window — the menu becomes a hamburger.
